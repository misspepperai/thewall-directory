# GA4 configuration — required one-time setup in the GA4 UI

Property: **The Wall** · Measurement ID **G-7EVW8MX8Z9** · tracking live since 2026-08-04

The tracking code is deployed and firing. **But GA4 will not show you the event
parameters until you register them as custom dimensions.** This is the part everyone
skips and then wonders why every report says `(not set)`.

Two tasks, ~10 minutes. Task A is the one that matters.

---

## Task A — Register custom dimensions (~7 min)

**Admin** (gear, bottom left) → under *Data display* → **Custom definitions** →
**Create custom dimension**. Repeat for each row below.

Scope is **Event** for all of them. Description is optional.

| Dimension name | Scope | Event parameter | What it answers |
|---|---|---|---|
| Page type | Event | `page_type` | Which *kind* of page earns engagement — listing vs pillar vs hub vs briefing |
| Vendor domain | Event | `vendor_domain` | Which specific vendors get looked at, and who claims |
| Vendor name | Event | `vendor_name` | Same, human-readable |
| Vendor category | Event | `vendor_category` | Which disciplines pull traffic |
| Link location | Event | `link_location` | Where partner clicks come from — claim block vs nav vs homepage CTA |
| Nav group | Event | `nav_group` | Which nav dropdown gets used |
| Nav label | Event | `nav_label` | Which nav item gets used |
| Filter name | Event | `filter_name` | Which atlas filters people reach for |
| Filter value | Event | `filter_value` | What they filter *to* |
| Search term | Event | `search_term` | On-site searches — free keyword research |
| Question | Event | `question` | Which FAQ questions get opened |
| Chart | Event | `chart` | Which Data Corner chart got cited |
| Tool name | Event | `tool_name` | Tool usage |
| Tool category | Event | `tool_category` | What people benchmark |

⚠️ **GA4 only backfills from the moment you register.** A dimension registered on
Aug 10 shows nothing for Aug 4–9, even though the data was collected. Do this now
rather than after the first interesting week.

Free properties cap at 50 event-scoped custom dimensions. This uses 14.

---

## Task B — Mark key events (conversions) (~2 min)

**Admin** → *Data display* → **Events**. The events must have fired at least once to
appear in the list, so do this a day or two after launch.

Toggle **Mark as key event** on:

| Event | Why it's the conversion |
|---|---|
| `claim_click` | **The money event.** A vendor asking to claim + join the 10/20 deal. This is Weapon 1 landing without a cold email. |
| `correction_click` | Also a live vendor — different intent, same value: they're engaged and reachable |
| `partner_terms_click` | Top of the partner funnel |

Do **not** mark `vendor_outbound` as a key event. It's valuable to measure (it's the
10% side of the deal) but it's a *cost* as well as a benefit — it's traffic leaving.
Track it, don't optimise for it.

## The full event reference

Every event automatically carries `page_type`. Events on `/c/` pages also carry
`vendor_domain`, `vendor_name`, `vendor_category`.

### Funnel
| Event | Fires when | Extra params |
|---|---|---|
| `claim_click` | "CLAIM & COUNT ME IN" on a listing page | — |
| `correction_click` | "CORRECT THIS LISTING" | — |
| `partner_terms_click` | Any link to partner.html | `link_location`: claim_block, nav, homepage_cta, vendor_strip, footer, inline |
| `vendor_outbound` | "VISIT WEBSITE" → vendor's own site | `link_url` |
| `mailto_click` | Any other mailto link | `link_label` |

### Engagement
| Event | Fires when | Extra params |
|---|---|---|
| `faq_open` | A Q&A accordion is **opened** (not closed) | `question` |
| `nav_click` | Any top-nav link | `nav_group`, `nav_label`, `link_url` |
| `listing_open` | A vendor card is opened in the atlas | `vendor_domain`, `open_method` |
| `atlas_filter` | An atlas filter changes | `filter_name`, `filter_value` |
| `atlas_search` | On-site search, debounced 900ms, ≥3 chars | `search_term` |
| `compare_toggle` | Vendor added/removed from compare | `checked` |
| `compare_action` | Compare bar button | `action` |
| `cite_copy` | **CITE** on a Data Corner chart — journalist signal | `chart` |
| `tool_use` | Rate-benchmark calculator run | `tool_name`, `tool_category`, `tool_rate` |

`page_type` values: atlas, listing, pillar, hub, find, state, city, compare, question,
entity, briefing, update, report, tool, data_corner, win, badge, funnel, trust, other.

## Reports worth building once dimensions are registered

1. **Which page types convert** — Explore → free form → dimension `page_type`, metric
   Event count filtered to `claim_click`. Tells you whether listing pages are actually
   the funnel, or whether pillars/hubs do the work.
2. **Claim funnel by vendor category** — `vendor_category` × `claim_click`. Shows which
   disciplines are receptive before you spend a cold-email budget on them.
3. **On-site search terms** — `search_term`. Free keyword research from real buyers,
   and it feeds the next round of hub pages.
4. **Journalist interest** — `cite_copy` by `chart`. Which data actually gets cited.
5. **Partner funnel attribution** — `link_location` × `partner_terms_click`. Settles
   whether the homepage CTA, the vendor strip, or the listing claim block does the work.

## Verifying it works

**Realtime** (Reports → Realtime) shows events within ~30 seconds. Load a listing page
such as `https://hitthewall.net/c/108degrees.com.html`, open a Q&A accordion, and click
CLAIM — you should see `faq_open` and `claim_click` appear.

**DebugView** (Admin → DebugView) shows full parameter payloads, which Realtime does not.
To use it, install the *Google Analytics Debugger* Chrome extension and toggle it on.
This is the way to confirm `vendor_domain` etc. are actually attached.

Standard reports lag 24–48h. An empty Reports view the next morning is normal.

## Note for whoever maintains this

The tracking lives in `/nav.js`, which is loaded by all ~2,590 pages. That means event
changes ship with a one-file edit and no page rebuild — but it also means a syntax error
in `nav.js` breaks the nav site-wide. Before pushing a change to it, run:

```
node docs/track-test.mjs
```

It loads real pages into jsdom, runs the real `nav.js`, fires real events, and asserts on
the `gtag()` payloads. 40 assertions. It caught three genuine bugs during the initial
build, including one where an event silently never fired because a helper threw inside a
try/catch. Requires `npm install jsdom` in whatever directory you run it from.
